# 群聊协调说明

`GroupChatCoordinator` 负责选择角色、控制轮次和消息预算，并把每次发言交给单角色 `StateGraph`。单角色图负责检索、生成、校验和保存；协调器处理跳过、失败、反复读保护及房间事件。

## 模式与入口

`ChatSessionService.launchGeneration()` 根据会话模式创建协调器。房间配置包含 `mode`、`maxRounds`、`maxMessages`、`speakerPolicy`、`hostRoleId` 等字段。

- **定向回复**：指定 `targetRoleId` 或 `mentionTarget` 时，只调用目标角色一次，与房间模式无关。
- **一轮回应**：每位参与角色本轮最多尝试一次，允许跳过和单角色失败。
- **自由群聊**：每次发言后重新选择下一位。有效的 `nextSpeaker` 优先；否则按候选顺序轮转。默认最多两轮、参与者数两倍的消息；没有待处理提名时可提前结束。
- **主持模式**：必须配置房间内的主持角色。主持人先开场；所有角色都可提名下一位。其他角色尝试完后，如有来宾实际发言且消息预算允许，主持人最多再尝试一次收尾，并可选择跳过。默认消息上限为参与者数加一。

## 逐条调度

一轮内用 `attempted` 记录已经尝试的角色。每条消息之后，协调器重新计算候选列表：

1. 当前轮次尚未尝试的有效提名优先。
2. 否则从未尝试角色中按房间顺序选择；`round_robin` 配置会轮换每轮起点。
3. 提名本轮已尝试的角色留到下一轮。自我提名和非房间成员提名被忽略。
4. 候选角色全部处理完后，只有待处理提名且未达到轮数上限才进入下一轮；否则结束。消息数和轮数始终是硬上限。

每个候选角色每轮最多调用一次；主持收尾是唯一允许主持人在同轮进行第二次尝试的例外。跳过和单角色失败不会阻止其他候选继续发言。取消生成会立即退出当前调度。

## 房间状态和事件

每次选择发言者时发布 `round_plan`，其中 `plannedSpeakers` 是**当前候选顺序**，会在同一轮内变化。界面显示为“候选发言”。协调器同时更新持久化的 `roomState.plannedSpeakers` 和 `currentTurn`。

保留的事件包括 `round_started`、`round_plan`、`round_stats`、`role_skipped` 和 `room_finished`。`room_finished.reason` 只有在主持人确实保存收尾消息时才写“主持人已收尾”；预算耗尽、自然结束和收尾跳过各有对应原因。

角色间接话的消息元数据以实际上一条消息作为 `replyToMessageId`，上一条为角色发言时记录其 `replyToRoleId`。`generationReason` 区分定向、提名、主持开场、主持收尾和普通调度。

## 反复读与记忆

协调器会比较同一角色上次已保存的回复。如果过于相似，会删除新回复并带反复读提示重试；再次重复则跳过。当前版本仍可能先通过 SSE 展示后来被删除的回复，流式草稿一致性留待下一阶段处理。

群聊结束后，会并行处理各参与角色的记忆。使用数字参数构造协调器的旧兼容路径仍存在；以上规则适用于正式房间配置路径。
